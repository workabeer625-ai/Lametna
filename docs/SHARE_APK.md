# مشاركة التطبيق مباشرة (APK) — بلا Google Play

هذا الدليل لتوزيع «لمّتنا» على أصدقائك مباشرة: تبني ملف **APK** واحد، ترسله عبر
واتساب أو تيليجرام أو رابط تحميل، ويثبّته المستلم بنقرتين.

> للنشر في متجر Play (ملف `.aab`) راجع `docs/DEPLOYMENT.md` — القسم 5.

---

## 0. قبل أي شيء: الفرق بين APK و AAB

| الملف | لمن | يُثبَّت مباشرة؟ |
|-------|-----|-----------------|
| **`.apk`** | المشاركة المباشرة (حالتك) | ✅ نعم |
| `.aab` | Google Play فقط | ❌ لا |

فابنِ دائمًا `flutter build apk` وليس `appbundle`.

---

## 1. متطلبات مرّة واحدة

| المتطلب | التحقق |
|---------|--------|
| Flutter SDK | `flutter doctor` بلا أخطاء حمراء |
| Java JDK 17 | `java -version` |
| Android SDK + قبول التراخيص | `flutter doctor --android-licenses` |
| ملف `env.json` في جذر المشروع | موجود (غير مُتتبَّع في Git) |

محتوى `env.json` (القيم من Supabase → Settings → API):

```json
{
  "SUPABASE_URL": "https://YOUR-REF.supabase.co",
  "SUPABASE_ANON_KEY": "YOUR_PUBLIC_ANON_KEY",
  "APP_ENV": "prod"
}
```

> ⚠️ لو بنيت بدون `--dart-define-from-file=env.json` سيفتح التطبيق على شاشة
> «إعدادات الخادم غير مضبوطة» عند كل الناس. السكربت في الخطوة 4 يمنع هذا الخطأ.

## 2. مفتاح التوقيع (خطوة واحدة للأبد)

كل APK يجب أن يكون موقَّعًا. إن وقّعت بمفتاح debug فسيعمل التطبيق، لكن **أي
تحديث لاحق لن يُثبَّت فوق القديم** وسيُطالب المستخدم بحذف التطبيق وإعادة تثبيته.
لذا أنشئ مفتاحك مرة واحدة واحتفظ به للأبد.

في PowerShell من جذر المشروع:

```powershell
keytool -genkey -v `
  -keystore F:\lametna-keystore.jks `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -alias lametna
```

> لو قال «keytool غير معروف» استخدم المسار الكامل، مثل:
> `"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe"`

سيسألك عن كلمة مرور (احفظها!) ثم بعض البيانات (الاسم/المدينة… يكفي أي قيمة).

ثم أنشئ الملف `android\key.properties`:

```properties
storePassword=كلمة_المرور_التي_أدخلتها
keyPassword=كلمة_المرور_نفسها
keyAlias=lametna
storeFile=F:\\lametna-keystore.jks
```

> - استخدم `\\` المزدوجة في المسار على ويندوز.
> - `key.properties` و `*.jks` مستثنيان من Git تلقائيًا — **لا ترفعهما أبدًا**.
> - انسخ ملف `.jks` احتياطيًا في مكان آمن (Google Drive خاص مثلًا). فقدانه = فقدان القدرة على التحديث.

## 3. رقم النسخة

قبل كل توزيع جديد ارفع الرقم في `pubspec.yaml`:

```yaml
version: 1.0.1+2      # 1.0.1 = ما يراه المستخدم، +2 = رقم البناء (يجب أن يزيد دائمًا)
```

بدون زيادة `+N` سيرفض أندرويد تثبيت النسخة الجديدة فوق القديمة.

## 4. البناء

### الطريقة السهلة (سكربت جاهز)

```powershell
cd F:\lametna
powershell -ExecutionPolicy Bypass -File tool\build_apk.ps1
```

السكربت يتحقّق من `env.json` ومن مفتاح التوقيع، ثم يبني ويطبع مسار الملف وحجمه.

### الطريقة اليدوية

```powershell
cd F:\lametna
flutter pub get
flutter build apk --release --dart-define-from-file=env.json
```

الناتج:

```
build\app\outputs\flutter-apk\app-release.apk        ← هذا الذي ترسله (~40–55 ميجا)
```

### نسخة أصغر لكل معمارية (اختياري)

```powershell
flutter build apk --release --dart-define-from-file=env.json --split-per-abi
```

الناتج ثلاثة ملفات:

| الملف | الأجهزة |
|-------|---------|
| `app-arm64-v8a-release.apk` | ✅ كل الهواتف الحديثة (99٪) — أرسل هذا |
| `app-armeabi-v7a-release.apk` | هواتف قديمة جدًا (32-bit) |
| `app-x86_64-release.apk` | المحاكيات فقط |

الحجم ينزل إلى ~18–22 ميجا، لكن إن أخطأ أحدهم في اختيار الملف لن يُثبَّت.
لو ترسل لناس عاديين: **ابقَ على `app-release.apk` الموحّد**.

## 5. التوزيع على الناس

1. **واتساب**: أرسل الملف كـ «مستند» (Document) لا كصورة.
   واتساب يقبل حتى 2 جيجا، فالحجم ليس مشكلة.
2. **تيليجرام**: الأفضل — يحافظ على الملف بلا ضغط وينشئ رابطًا دائمًا.
3. **رابط تحميل مجاني ودائم**: أنشئ Release في GitHub وارفق الـ APK:

```powershell
gh release create v1.0.0 build\app\outputs\flutter-apk\app-release.apk `
  --title "لمّتنا 1.0.0" --notes "أول إصدار للتجربة"
```

   ثم شارك رابط الصفحة — يحمّل منه أي أحد بلا حساب.
4. بدائل: Google Drive (شارك «لأي شخص لديه الرابط»)، أو Firebase App
   Distribution / Diawi لو أردت توزيعًا منظّمًا بمجموعات مختبِرين.

### ماذا يفعل المستلم؟

1. يحمّل الملف ويفتحه من الإشعار أو من مجلد «التنزيلات».
2. يظهر تحذير «لأسباب أمنية لا يُسمح بتثبيت تطبيقات من هذا المصدر» →
   **الإعدادات** ← تفعيل «السماح من هذا المصدر» ← رجوع ← **تثبيت**.
3. قد يظهر Play Protect «تطبيق غير معروف» → **التثبيت على أي حال**
   (طبيعي لأي تطبيق خارج المتجر).
4. أندرويد 6 فأحدث مطلوب (minSdk 23).

أرسل لهم هذه الجملة الجاهزة مع الملف:

> حمّل الملف وافتحه، لو ظهر تحذير «مصدر غير معروف» اضغط «إعدادات» وفعّل السماح،
> ولو ظهر تحذير من Play Protect اضغط «تثبيت على أي حال». التطبيق آمن ولا يطلب أي
> صلاحية غير الإنترنت.

## 6. ما الذي يراه الناس داخل التطبيق؟

- **لا يحتاجون شيئًا منك**: كل شيء يعمل عبر Supabase الخاص بك مباشرة.
- **تأكد قبل التوزيع** أن الخادم جاهز: الترحيلات مطبّقة، البذور موجودة،
  دوال الحافة منشورة، وجدولة `tick-rounds` تعمل (راجع `docs/DEPLOYMENT.md`).
  بدون `tick-rounds` لن تنتهي الجولات تلقائيًا عند اللاعبين.
- **خطة Supabase المجانية** تكفي عشرات اللاعبين المتزامنين؛ راقب
  Database → Reports لو زاد العدد.

## 7. الأمان — ماذا يوجد داخل الـ APK؟

| القيمة | داخل الـ APK؟ | آمن؟ |
|--------|---------------|------|
| `SUPABASE_URL` | نعم | ✅ عام بطبيعته |
| `SUPABASE_ANON_KEY` | نعم | ✅ مفتاح عام، محمي بـ RLS |
| `service_role key` | **لا، أبدًا** | ❌ لو وضعته ينكشف كل شيء |

أي شخص يستطيع استخراج المفتاح العام من أي تطبيق، ولهذا الحماية الحقيقية هي
سياسات **Row Level Security** في قاعدة البيانات — وهي مفعّلة في هذا المشروع.
لا تضع أي مفتاح سري في `env.json`.

## 8. التحديثات لاحقًا

```powershell
# 1) عدّل الكود
# 2) ارفع الرقم في pubspec.yaml:  version: 1.0.1+2
# 3) ابنِ بالمفتاح نفسه:
powershell -ExecutionPolicy Bypass -File tool\build_apk.ps1
# 4) أرسل الملف الجديد — يثبَّت فوق القديم وتبقى بيانات المستخدم
```

شرط استمرار التحديث: **نفس ملف `.jks` ونفس `applicationId`** (`app.lametna.lametna`).

## 9. الآيفون؟

لا يمكن مشاركة تطبيق iOS كملف كما في أندرويد. تحتاج:

- حساب Apple Developer (99$ سنويًا) + **TestFlight** — حتى 10,000 مختبِر بدعوة، وهو الأسهل، أو
- تثبيت بالكابل عبر Xcode لكل جهاز على حدة (شهادة مجانية تنتهي كل 7 أيام).

## 10. حلّ المشكلات

| العَرَض | السبب | الحل |
|---------|-------|------|
| شاشة «إعدادات الخادم غير مضبوطة» | نسيت `--dart-define-from-file=env.json` | أعد البناء بالسكربت |
| التطبيق يفتح ثم «لا يوجد اتصال» عند الجميع | صلاحية INTERNET ناقصة في manifest الإصدار | مثبَّتة الآن في المستودع — تأكد أنك محدَّث |
| «التطبيق غير مثبَّت» عند المستلم | نسخة أقدم موقّعة بمفتاح مختلف | يحذف القديم ثم يثبّت، ووحّد المفتاح لاحقًا |
| «حزمة تبدو تالفة» | رفعت الملف عبر وسيط ضغطه | أرسله كمستند/عبر تيليجرام |
| فشل التوقيع أثناء البناء | مسار خاطئ في `key.properties` | مسار مطلق مع `\\` مزدوجة |
| `Execution failed ... minSdkVersion` | جهاز أقدم من أندرويد 6 | غير مدعوم |
| البناء بطيء جدًا أول مرة | Gradle يحمّل التبعيات | طبيعي (5–15 دقيقة)، والمرات التالية أسرع |
